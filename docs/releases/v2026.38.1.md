# v2026.38.1 — authcore onto its first release, and a hardened release path

The second artifact set of week 38. No product behaviour changed: this revision is the identity
library moving off a pinned commit and onto a tagged version, the dependency refreshes that were
waiting behind it, and repairs to the release path itself.

## Compatibility

Unchanged from v2026.38. **This release requires the v0.4.72 database schema** and, like that one, it
converts nothing: there is no DDL, no backfill, and no stamping. A database that v2026.38 started
starts here unchanged, and a rollback to v2026.38 is clean — nothing in either direction touches the
schema, `config.yaml`, or key material.

## Changed

### The shared identity library is a dependency again, not a commit pin

`authcore` — SAML, passkey, captcha and geoip — was pinned to commit `9936873` because the library
had no tags when the portal adopted it. It is now **v0.4.0**: that commit plus nine, and the first
release there is to depend on.

The portal's four adapters need no change, and that was checked rather than assumed:

- `saml` gains `Assertion.AttributesByName`, indexed by an attribute's `Name` alone. Additive and
  unread here: the portal indexes by `Name` *and* `FriendlyName` and sets `StrictAttributes: true`,
  so it refuses an ambiguous pair instead of disambiguating one.
- `passkey`'s three changed files are comments, but they state the `UpdateSignCount` contract and pin
  it with a test: a non-nil error fails the ceremony and returns a nil `*LoginResult`. The portal's
  store never returns one — it declines the write when the clone warning is set, and the handler
  refuses the login from the result — so the login path, including the `cloned_authenticator` audit
  entry, is exactly as it was.
- `captcha` and `geoip` are untouched in the range, and `authcore/ratelimit`, removed upstream, was
  never imported.

Dependabot tracks tagged versions only, so from here the pin cannot drift onto an unreleased commit
unnoticed.

### Dependency refreshes

Go: `pgx` 5.11, `goldmark` 1.8.6, `oauth2` 0.37, `sqlite` 1.59 (with `libc` and `memory`).
Web: React 19.3, `antd` 6.6.4, `vite` 8.3, `react-router` 8.4, `katex` 0.18, `i18next` 26.4,
`opencc-js` 1.4.2, and `vitest` 5.0.1 in its own pull request because it is a major. `dompurify` and
`mermaid` were deliberately left out of the batch and still get reviewed alone: both handle content
the portal did not author.

### The release path

The last release exercised this path hard enough to show where it was wrong, and the repairs landed
here:

- **The release workflow uses no shared cache**, and the guard that validates a release runs from the
  default branch rather than from the ref it is validating — a guard supplied by the thing it guards
  is not a guard. The same reasoning the build job already applied to its own outputs.
- **The container smoke test tolerates a connection reset** while the container restarts. A reset is
  neither a refused connection nor a timeout, and catching only those two made the check fail
  deterministically at the restart layer — and, it being one of the required status checks, block
  every pull request.
- **Channel alignment reads GitHub's `Latest` field before writing it.** It used to PATCH
  unconditionally, a PATCH fires `release edited`, and that event starts the same workflow: publishing
  v2026.38 produced 31 runs in six minutes. A stale field is still corrected, on the run that was
  going to happen anyway.
- **Release metadata can be recovered** by comparing the archive binaries against the pushed image
  byte for byte, instead of rebuilding and replacing them.
- **`derive_version` no longer matches notes and tags with a `v<week>*` glob.** A week has no leading
  zero, so `v2026.3` is a prefix of `v2026.30` — in weeks 1 through 9 the derivation could hand back
  another week's number, or this week's number carrying another week's revision. The week is a
  parameter now, and `scripts/release_derive_test.sh` checks weeks 1, 9, 53 and a year rollover in
  throwaway repositories rather than by waiting for a date.
- **The e2e check's output is English**, as this project's rule requires of anything a developer
  reads, a CI log included. The Chinese that remains is data: report subtypes and titles, OU and
  version names, and the body text the checks assert on. Those exercise the product's real
  Chinese-data paths.

### The upgrade ladder

`ensureColumns` and `reconcileReportVersions` are back under their own names as the ladder's entry
points — empty, because the runtime sits at a database baseline and converts nothing — and `init`
calls both on every path. A future upgrade is a function body and a call, never a new startup path.

## Fixed

The audit page's phone-layout test no longer races antd's `Spin`, which sets `pointer-events: none`
while it spins: a card appearing is not a card being tappable, and the node has to be re-queried
inside the wait *and* for the click, because a detached node reports no `pointer-events` and so looks
reachable. `main` had gone red on it on a loaded runner. Test-only.

## Rollback

Restore the **v2026.38** binary or image. No database, configuration or key-material step is involved
in either direction.
